# Pinch wishlist backend

A Node.js API backed by MongoDB, serving the existing frontend and one shared wishlist. **There is no authentication or authorization**: anyone who can reach the server can read and add items. Do not expose it publicly unless that is intended; use network access controls if needed. This is not a per-user or private wishlist.

## Setup

Requires Node.js 20 or newer and a MongoDB database (such as Atlas). Create a database user, allow your server's IP in Atlas network access, and obtain its connection string. Run:

```sh
npm install
cp .env.example .env
# Set MONGODB_URI in .env, keeping credentials private
npm start
```

`MONGODB_URI` is required; `MONGODB_DB_NAME` defaults to `pinch` and overrides any database specified in the URI. `PORT` defaults to `3000`. The server connects and pings MongoDB before listening. Visit `http://localhost:3000/`. Never commit `.env` or credentials. Only the `public/` folder is served to the browser; server code, tests and config are not.

Open the app through the server URL, not directly as a `file://` page. The frontend loads and saves wishlist items through the API. On subsequent visits, an existing wishlist opens after the splash screen; an empty wishlist starts the onboarding flow. Uploaded JPEG, PNG, GIF and WebP images are limited to 2 MiB.

## API

JSON responses use `Content-Type: application/json`.

- `GET /api/items`: `200 { "items": [item, ...] }`, ordered by MongoDB `_id` ascending.
- `POST /api/items`: send a JSON object with `Content-Type: application/json`; returns `201 { "item": item }`.
- MongoDB items include a UTC `createdAt` timestamp when available, used to display calendar lock and unlock dates.
- Errors have the form `{ "error": "message" }`: `400` for invalid fields or malformed JSON, `413` for a request exceeding the 3 MiB JSON body limit, `404` for unknown routes, and `500` for database or server errors.

- `PATCH /api/items/:id`: send any subset of the item fields below (same rules; `name` stays nonblank); returns `200 { "item": item }`, or `404` if the item does not exist.
- `DELETE /api/items/:id`: removes the item; returns `204`, or `404` if it does not exist.
- `GET /api/settings`: `200 { "settings": settings }`, using defaults for anything not yet saved.
- `PUT /api/settings`: send any subset of the settings fields; returns `200 { "settings": settings }` with the merged result. Settings are shared like the wishlist and stored as one document in the `settings` collection.

| Setting | Accepted input | Default |
| --- | --- | --- |
| `currency` | `CAD`, `USD`, `EUR`, `GBP` or `AUD`; preselected when adding items | `"CAD"` |
| `defaultLockDuration` | `""`, `1 Day`, `1 Week`, `2 Weeks` or `1 Month`; preselected when adding items | `""` |
| `taxRate` | Number from 0 to 30 (percent) | `13` |
| `showTaxInCost` | Boolean; when on, home cards show price plus tax as "True cost" | `true` |
| `categories` | Up to 12 `{ name, color }` objects; names 1–30 characters, unique, not `All`; colors `purple`, `green`, `blue`, `coral`, `orange` or `grey`. Used for home filters and goal choices | Essentials, Education, Fashion, Travel |

An item has an `id` string generated by MongoDB and these fields:

| Field | Accepted input | Default |
| --- | --- | --- |
| `name` | Required nonblank string, up to 200 characters; surrounding whitespace is trimmed | none |
| `price` | Nonnegative finite number, decimal numeric string (including exponent notation), or empty string; numeric strings up to 50 characters | `""` |
| `currency` | String up to 10 characters | `"CAD"` |
| `image` | `null` or canonical base64 data URL with MIME `image/jpeg`, `image/png`, `image/gif`, or `image/webp`; decoded data must be nonempty and at most 2 MiB | `null` |
| `goal`, `urgency`, `lockDuration`, `feeling` | Strings up to 100 characters each | `""` |
| `goals` | Up to 12 unique category names (1–100 characters). `goal` is kept equal to the first one; items saved before this field existed return `[goal]` | `[]` |
| `store` | String up to 200 characters | `""` |
| `boughtAt` | ISO date string when the item was bought, or `null` | `null` |
| `notes` | Up to 100 `{ text, createdAt }` objects; `text` 1–500 characters, `createdAt` an ISO date string | `[]` |

All fields other than `name` are optional. Unknown fields and wrong types are rejected. Image validation checks the declared MIME and base64 encoding/size, not whether the decoded bytes form a valid image. Price retains its submitted number or string type. The overall request limit accommodates a 2 MiB image encoded as base64 plus normal item fields.

Example:

```sh
curl -X POST http://localhost:3000/api/items -H 'Content-Type: application/json' \
  -d '{"name":"Notebook","price":"12.50","currency":"CAD","goal":"Education"}'
curl http://localhost:3000/api/items
```

## Tests

Run `npm test`. Tests exercise HTTP routes against an in-memory collection double; they do not require or modify Atlas. A live Atlas connection requires valid credentials and network access and is not covered by these tests.
